# 《高性价比人生指南》小程序 · 产品重设计与 UI 规范

> 角色：产品负责人（PM）视角的完整体检 + 重设计方案
> 输入：现有 12 个页面（4 tab + 8 二级/子包页）、676 条建议 / 34 节 / 9 篇长文 / 136 篇核实记录 / 41 条术语 / 522 处交叉引用
> 输出：产品诊断 → 信息架构 → 关键流程 → UI 设计系统 → 优先级排期

---

## 0. 一句话结论

**内容资产已经足够好，问题在「把知识变成行动」这一步没有闭环。**

现在的小程序是一本**优秀的查阅工具书**（能搜、能查、标注克制、离线可读），
但它没有回答用户每次打开时最关心的那句话：**「我今天该做哪一条？」**

重设计的核心不是换皮，是补上**行动闭环**：`今天做一条 → 读到能懂 → 加进清单 → 打勾`，
并把这个闭环的入口从「首页第 5 屏」提到「首屏第一眼」。

## 1. 定位再校准

### 1.1 用户与场景（谁、什么时候、为什么打开）

| 场景 | 用户当时的状态 | 期望（JTBD） | 现状满足度 |
| --- | --- | --- | --- |
| **S1 临时查证** | 刚看到一个说法（「低钠盐到底行不行」），半信半疑 | 30 秒内拿到结论 + 证据强度 + 值不值得做 | ✅ 基本满足（检索强） |
| **S2 焦虑驱动** | 深夜、体检报告异常、家人生病 | 知道「现在最该做的那一两件事」，并且做得到 | ⚠️ 部分满足（能找到，但选择成本高） |
| **S3 主动改善** | 想系统性改变（戒烟、存钱、换工作） | 有一个可持续推进的清单和节奏 | ❌ 未满足（清单只是收藏夹） |
| **S4 离线阅读** | 地铁、飞机、医院候诊、断网 | 全书可读，且知道自己「存全了」 | ⚠️ 功能有，感知弱 |

**关键洞察**：S2 和 S3 是高价值场景（高频 + 高情绪），而现有产品的信息架构是按
**「书的结构」**（节 → 条目）组织的，不是按**「人的处境」**组织的。S1 做得很好，
S2/S3 缺。

### 1.2 价值主张（一句话）

> **把「该做的」按值不值得做排好序，告诉你为什么，然后让你做得到。**

三个不可替代的资产：

1. **证据分级 × 性价比 双轴标注** —— 市面上没有第二个中文生活建议产品做这件事；
2. **交叉引用网络**（522 处）—— 建议之间互相指路，形成知识图谱而不是词典；
3. **完全离线 + 无账号** —— 只存 openid，不登录、不采集。

### 1.3 明确不做（防止范围蔓延）

- 不做 AI 问答（第一版既定边界，内容可追溯性优先于对话体验）；
- 不做社区/UGC（672 条建议的权威性来自单一作者 + 逐条核实，混入 UGC 会稀释）；
- 不做打卡排行榜/游戏化等级（这本书的调性是「挑一两条先做」，不是刷量）。

## 2. 现状诊断（体验走查）

按三个典型任务实际走一遍，记录摩擦点。**P0 = 阻断决策，P1 = 明显降效，P2 = 体验粗糙。**

### 任务 A：我有高血压，现在最该做什么？

| 步骤 | 现状 | 摩擦 |
| --- | --- | --- |
| 打开小程序 | 首屏是书封 + 版本条 + 搜索框 + 「按问题找」列表 | 首屏有效信息只有「按问题找」，但被压在第 3 屏 |
| 找入口 | 「按问题找」34 个问题，2 行一个问题，滚动找 | **P1**：34 个问题无分类、无搜索，找「血压」要滑 |
| 进节详情 | 落到「不要早死」第 1 节，43 条，按性价比排序 | ⚠️ 43 条按性价比排，但用户的目标是**病**不是**节** |
| 找具体条目 | 靠节前「分组导览」+ 肉眼扫 | **P1**：43 条里定位「血压相关」仍需逐条读标题 |
| 读条目 | 「说人话」在成本签下面，页面第三块 | ✅ 内容质量高，但**首屏没看到结论** |

**结论**：任务 A 需要 5 步、2 次长滚动，**P0 缺失**：没有「按症状/处境」直达条目的路径。

### 任务 B：把书存到手机，明天飞机上读

| 步骤 | 现状 | 摩擦 |
| --- | --- | --- |
| 找入口 | 首页第 6 屏「离线」区块里的 rowcard | **P0**：这是产品最强差异点，却在最深处 |
| 下载 | 点一下开始，显示进度条 | ✅ 可续传 |
| 完成后 | toast「全书已存到本机」+ 文案变成「已完整存到本机，断网也能读」 | **P1**：没有「存了多少 MB / 多少条」的实感，无徽章，不可分享 |

### 任务 C：我决定戒烟，想认真推进

| 步骤 | 现状 | 摩擦 |
| --- | --- | --- |
| 加清单 | 条目详情底部「加进清单」 | ✅ 路径短 |
| 回清单看 | 「要做的」页，进度条 `3 / 12 · 25%` | **P0**：没有优先级、没有节奏、没有「本周」概念 |
| 推进 | 手动逐条打勾 | **P1**：无提醒、无连续天数、无「做完了之后干什么」 |

**清单页的结构性问题**：它把「收藏」和「待办」混在一个进度条里。
进度条 `3 / 12` 隐含「做完 12 条就完成」，而这本书的用法恰恰是「挑一两条先做」——
**UI 在鼓励错误的心智模型**。

### 问题汇总（按优先级）

| # | 问题 | 优先级 | 影响场景 | 证据 |
| --- | --- | --- | --- | --- |
| 1 | 没有「按处境/症状」直达建议的入口 | **P0** | S1 S2 | 34 问题无分类；只能按节找 |
| 2 | 首页是导航目录的堆叠，首屏无行动焦点 | **P0** | 全部 | 首页 8 个 label 区块、12 个可点行 |
| 3 | 清单是收藏夹，不是行动清单（无优先级/节奏/连续） | **P0** | S3 | 进度条 `n / m` 与产品用法冲突 |
| 4 | 离线下载是设置项，不是价值主张 | **P1** | S4 | 入口在第 6 屏；完成无实感 |
| 5 | 检索结果按相关度排，不按「值得做」分层 | **P1** | S1 S2 | 结果卡无优先级分组 |
| 6 | 条目详情首屏看不到结论（说人话在第 3 块） | **P1** | S1 S2 | 成本签 + 标记占了首屏 |
| 7 | 「证据等级 / 性价比」语言无首次引导 | **P1** | 新用户 | 只在关于页有入口 |
| 8 | 版本号对用户无意义（`v20261009-6e1d6fb`） | **P2** | S2 | 关于页首行 |

## 3. 指标体系

| 层级 | 指标 | 定义 | 现状基线 | 目标 |
| --- | --- | --- | --- | --- |
| **北极星** | 周行动闭环数 | 一周内完成「读条目 → 加清单 → 打勾」≥1 次的用户数 | 未埋点 | 建立埋点，重设计后 +100% |
| 一级 | 首屏行动点击率 | 首屏「今天做一条」/问题入口点击 / 启动数 | — | ≥ 40% |
| 一级 | 查找成功率 | 3 次操作内到达目标条目 / 查找会话 | — | ≥ 85% |
| 一级 | 清单激活率 | 清单页有 ≥1 条且 ≥1 条打勾的用户占比 | — | ≥ 30% |
| 二级 | 离线完成率 | 点击「下载全书」后完成的比例 | — | ≥ 70% |
| 二级 | 检索零结果率 | 有搜索但 0 命中的会话占比 | — | ≤ 10% |
| 护栏 | 内容严谨性 | 断网可读条目占比 / 有来源条目占比 | 100% 有来源 | 不下降 |

> 埋点建议（小程序自带的 `wx.reportEvent` 或云函数写 `events` 集合）：
> `page_view` / `entry_from`（记录入口来源）/ `item_open` / `list_add` / `checkin_done` / `search_hit` / `offline_done`。

## 4. 信息架构重设计

### 4.1 Tab 结构（前后对比）

| | 现状 | 重设计后 | 变更理由 |
| --- | --- | --- | --- |
| Tab 1 | **指南**（书封 + 34 问题 + 目录 + 材料 + 离线 + 版本） | **今天**（今天做一条 + 找问题 + 快速入口 + 离线状态条） | 把「导航目录」变成「行动起点」 |
| Tab 2 | **检索** | **检索**（结果按可执行性分层 + 一键加清单） | 强化决策属性 |
| Tab 3 | **清单**（收藏 + 待办 + 进度条） | **清单**（今天 / 稍后 / 已完成 三段 + 连续天数 + 收藏独立） | 从收藏夹 → 行动看板 |
| Tab 4 | **关于**（版本 + 读法 + 版权 + 免责 + 更新） | **我的**（更新于 X 月 X 日 · N 条 / 阅读设置 / 离线管理 / 关于与许可） | 把「设置」和「说明」分开，用日期代替 commit |

### 4.2 页面层级

```
今天 (tab1)
├── 今天做一条 ─────────────────────→ 条目详情
├── 找问题（34 个，按「身体 / 钱 / 时间 / 关系 / 风险」分类）
│     └─────────────────────────────→ 节详情（高亮相关条目）
├── 按节读 → 节列表 → 节详情 ────────→ 条目详情
└── 书以外的材料 → 长文 / 核实记录 / 引用对照 / 术语表

检索 (tab2) → 结果（分层） ────────→ 条目详情 / 长文
清单 (tab3) → 今天 / 稍后 / 已完成 / 收藏 ─→ 条目详情
我的 (tab4) → 版本与更新 / 阅读设置 / 离线管理 / 关于与许可 / 免责
```

### 4.3 「找问题」的分类（新）

34 个问题现在是一条平铺列表。重设计按**用户处境**分五组，每组给一个语义色点：

| 组 | 问题示例（真实数据） | 色 |
| --- | --- | --- |
| **身体与安全** | 几乎不花钱就能明显降低早死概率的事有哪些？ | 柏绿 |
| **日常习惯** | 抽烟、喝酒、久坐、熬夜到底折寿多少？ | 柏绿 |
| **钱与工作** | 换工作、换城市之前要算哪几本账？ | 赭黄 |
| **关系与家庭** | 孩子出生前后要办的事？结婚划不划算？ | 赭黄 |
| **时间与精力** | 每天精力不够用、总被打断，怎么改？ | 石灰 |

> 分类依据：`essentials.problems[].sec` → 34 节的 5 大板块（1-5 身体、6-15 钱/时间、16-25 关系/生活、26-34 风险与制度）。落地时在 `essentials.js` 里加 `group` 字段即可，**不需要改上游内容**。

## 5. 关键流程（重设计后）

### 流程 1：S2 焦虑场景（最优路径 3 步 → 目标 2 步）

```
[今天] 首屏 ──点「今天做一条」─────────────→ [条目详情] 首屏即见结论 + 「加进清单」
     └──点「找问题 · 身体与安全」──→ [问题列表(分类)] ──→ [节详情] ──→ [条目详情]

```

### 流程 2：S3 行动场景（新增闭环）

```
[条目详情] 「加进清单」─→ [清单] 今天(1) ─→ 打勾 ─→ 连续 3 天 ▸ 提示「要不要再挑一条？」
```

### 流程 3：S4 离线场景（入口前置 + 完成实感）

```
[今天] 顶部离线状态条（未下载 / 已存 18.4 MB · 676 条 / 正在下载 62%）
        └─点开→ [离线管理] 全屏进度 + 完成后徽章「断网可读 ✓」
```

## 6. UI 设计系统 v2

现有设计语言（宋体内容 / 等宽数据 / 语义色 / 「找不到出处就不画」）**方向正确，保留**。
本次是**规范化 + 补可读性**，不是改风格。

### 6.1 色板

| 令牌 | 浅色 | 暗色 | 语义（只承载信息） |
| --- | --- | --- | --- |
| `--paper` | `#F4F5F2` | `#15181A` | 页面底 |
| `--card` | `#FFFFFF` | `#1D2124` | 卡片/浮层底 |
| `--line` / `--line2` | `#E3E4DF` / `#EDEEE9` | `#2C3135` / `#23282B` | 分隔 |
| `--ink` / `--ink2` / `--ink3` | `#191D1C` / `#5C635F` / `#8C918D` | `#E9EBE9` / `#A9B0AB` / `#8F9791` | 正文/次要/元信息 |
| `--green` | `#2F5D50` | `#7FBFA6` | 主色 = 证据 A = 可执行 |
| `--amber` | `#A9761B` | `#D6A855` | 证据 B / 需注意 |
| `--gray` | `#8C918D` | `#8C918D` | 证据 C |
| `--red` | `#9C3B2E` | `#D4796A` | 仅用于「争议 / 待核实」 |

**暗色对比度修正**（本次已落地）：`--ink3` 提到 `#8F9791`、`--green` 提到 `#7FBFA6`，
保证 22–24rpx 小字在 `#181B1D` 上 ≥ 4.5:1。

### 6.2 字阶（新增规范，含可读性提升）

| 角色 | 字号 | 字体 | 用途 |
| --- | --- | --- | --- |
| 书名 | 44rpx | 宋 | 首屏唯一大标题 |
| 条目标题 | 36rpx（原 32） | 宋 | 列表行标题 |
| 正文 | 30rpx（原 28，**下限 26**） | 宋 | 「说人话」/ 长文 |
| 摘要 | 26rpx（原 23） | 黑 | 列表预览 2 行 |
| 数据/标签 | 22–24rpx | 等宽 | 数字、条号、筛选 |
| 元信息 | 22rpx（原 21） | 等宽 | 版本、来源 |

> 规则：**一切数字用等宽 + `tabular-nums`**；正文（宋）行高 1.85，界面（黑）1.6。

### 6.3 组件规范（升级点）

| 组件 | 现状 | 升级 |
| --- | --- | --- |
| 条目卡 | 条号 + 标题 + 摘要 + 成本签 + 证据/性价比 | **同一卡在「今天」页加一个「加进清单」快捷动作**（列表层即可行动，无需进详情） |
| 成本签（五格） | 钱/时间/毅力/收益/口径，等宽表 | 保留（这是产品指纹），「不用毅力 / 不花钱」用主色轻底标注，一眼看到「零成本」 |
| 证据徽章 | A/B/C 明度递降 | 保留，补一句 hover/长按说明「A = 数字最可信」 |
| 性价比条 | 三格 | 保留，列表层增加「极高」的排序暗示（顶部一条极细分隔） |
| 离线状态条 | 无 | **新增**：常驻首屏顶部，三态（未存 / 下载中 x% / 已存 18.4MB · 断网可读） |
| 清单行 | 勾 + 删除 | 增加「今天 / 稍后」分组、长按拖动、连续天数 |
| 按钮 | 主/次/幽灵 | 不变，但**每个屏幕只允许一个主按钮** |

### 6.4 动效

- 只保留三处：**打勾**（勾号描边 200ms）、**进度条**（宽度过渡）、
  **页面进入**（唯一一处 240ms 上移淡入，仅首屏）。
- 不加：卡片逐条入场、悬浮放大、渐变装饰。

## 7. 优先级排期（RICE 简化）

| 序 | 事项 | 触达 | 影响 | 信心 | 成本 | 结论 |
| --- | --- | --- | --- | --- | --- | --- |
| 1 | 首页重构：今天做一条 + 找问题前置 + 分类 | 高 | 高 | 高 | 中 | **P0 做** |
| 2 | 问题列表按 5 组分类（含 `group` 字段） | 高 | 高 | 高 | 低 | **P0 做** |
| 3 | 条目详情：说人话提到首屏 + 底部动作条固定 | 高 | 中 | 高 | 低 | **P0 做** |
| 4 | 清单升级为行动看板（今天/稍后/已完成 + 连续） | 中 | 高 | 中 | 中 | **P0 做** |
| 5 | 离线状态条 + 全屏下载流程 + 完成徽章 | 中 | 中 | 高 | 低 | **P1 做** |
| 6 | 检索结果按性价比分层 + 卡片快捷加清单 | 中 | 中 | 中 | 中 | **P1 做** |
| 7 | 我的页重排：日期代替 commit + 阅读设置（字号/主题） | 中 | 中 | 高 | 低 | **P1 做** |
| 8 | 埋点（7 个事件） | — | 高 | 高 | 低 | **P1 做** |
| 9 | 字号阶梯全站上调（26rpx 下限） | 高 | 中 | 高 | 低 | **P1 做** |
| 10 | 新用户 3 屏引导（证据/性价比怎么读） | 中 | 中 | 中 | 低 | P2 |
| 11 | 分享单条建议为图片卡片 | 中 | 低 | 中 | 中 | P2 |

**建议节奏**：第一批 1–4（首页 + 详情 + 清单）一次做完，因为三者共享数据结构；
第二批 5–9（离线 + 检索 + 我的 + 埋点 + 字号）；P2 待数据验证后再定。

## 8. 风险与对策

| 风险 | 对策 |
| --- | --- |
| 「今天做一条」随机推荐可能推给不适合的人（如给孕妇推戒烟药） | 改为**基于清单 / 最近浏览的节**推荐，且明确标注「随机一条 · 换一条」；不做个性化画像 |
| 首页重构削弱了「按节读」的老用户路径 | 保留「按节读」入口（降为次一级），不删功能只改层级 |
| 清单分组增加复杂度 | 默认只显示「今天」，稍后/已完成折叠 |
| 埋点引入隐私顾虑 | 只记事件名 + sid，不上传任何画像；在关于页明示 |

### 为什么 v3 要「去交互」

v2 里超过一半的交互（浅/暗切换、换一条、加清单、打勾、模拟下载）是为了**演示**，
不是为了**表达设计** —— 评审时要先点几下才看得清一屏长什么样。
v3 的目标是**一屏看完**：双击 HTML 即看，无需服务器、无需联网。

v3 的硬约束（每次改动都要守住）：

1. **零 `<script>`、零外链**（含字体，走系统字体栈）；
2. 机身内部按 375pt 逻辑宽书写（数值 = 小程序 rpx ÷ 2），
   `transform: scale(.853333)` 缩到 320px 展示 ⇒ 字号间距可以**直接和 `pages/**/index.wxss` 对读**；
3. 类名全 ASCII（沿用项目习惯，避免以后挪进小程序踩 WXSS 中文选择器的坑）；
4. 数据一律取自 `miniprogram/data/essentials.js` 的真实条目，不编造。

> 踩过的坑：`<figure>` 的 UA 样式用的是**逻辑属性** `margin-inline: 40px`，
> `* { margin: 0 }` 的物理 margin 覆盖不掉 ⇒ 每台机身被撑到 420px、第 5 台挤出画板。
> 必须显式写 `figure, figcaption { margin: 0; }`。
> 排查方法：**解码 PNG 扫描一行像素**量机身边界，比目测缩略图可靠。
